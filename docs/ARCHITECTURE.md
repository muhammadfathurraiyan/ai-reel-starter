# Architecture

How one frame gets built, and which file owns which decision. Read this before changing the
timeline model, the wipe, or the audio graph.

The repo is a **starter**, so everything here describes the shipped 2-scene example
(`intro` → `outro`, 240 frames). When you add scenes, keep the same contracts and this document
stays true.

---

## 1. Render graph

```
src/index.ts
└─ registerRoot(RemotionRoot)
   └─ src/Root.tsx
      └─ <Composition id="Reel" width={1080} height={1920} fps={30} durationInFrames={240}>
         └─ src/Reel.tsx
            ├─ <Backdrop />                        paper gradient, grid, frame, vignette
            ├─ <Sequence from={scene.from}>        one per scene
            │  └─ <SceneShell index duration overlap>
            │     └─ <Scene scene index>           scenes/Intro.tsx | scenes/Outro.tsx
            │        └─ <Captions sceneId frame>   words from voiceover.json
            └─ <Soundtrack />                      music + VO + SFX (no visuals)
```

`durationInFrames` is **computed** in `Root.tsx` as the sum of `scene.duration`, and `fps`,
`width`, `height` are read from the same file. The composition can therefore never disagree with
the timeline.

Composition id: **`Reel`**. It appears in `npm run render` / `npm run still` in `package.json`.
Rename all three together when you fork.

## 2. Timeline model

`src/data/scenes.json` is the only place that defines time. Every value is in **frames**.

```json
{
  "fps": 30,
  "width": 1080,
  "height": 1920,
  "scenes": [
    {
      "id": "intro",
      "label": "THE START",
      "title": "Make your next reel",
      "accent": "next",
      "note": "EDIT THE COPY IN src/data/scenes.json",
      "narration": "This is your starter reel. Make it yours.",
      "from": 0,
      "duration": 120
    }
  ]
}
```

| Field | Consumed by | Rule |
|---|---|---|
| `id` | `Reel.tsx` (`COMPONENTS`, `SCENE_FROM`), `voiceover.json`, `Captions` | unique, kebab-case |
| `label` | `Kicker` (small mono label) | short, uppercase |
| `title` | scene headline | free text; Anton renders it uppercase |
| `accent` | `withAccent` in `Text.tsx` | one word of `title` painted caramel |
| `note` | mono line under the headline | optional |
| `narration` | ElevenLabs prompt + caption source text | punctuation drives pacing |
| `from` | `Sequence` placement, checker | must equal previous `from + duration` |
| `duration` | scene length, VO window, composition length | positive integer frames |

Shipped boundaries: `0 → 120 → 240` (4.00 s + 4.00 s = 8.00 s).

The scene component receives `{ scene, index }` (`SceneProps` in `src/lib/types.ts`), so scenes
are pure functions of the data — no scene-specific constants baked into `Reel.tsx`.

## 3. Scenes and the wipe

`Reel.tsx` gives every scene but the last **10 extra frames** in its `Sequence`:

```ts
durationInFrames = scene.duration + overlap   // overlap = 10 for all but the last scene
```

`SceneShell` uses those frames to exit:

1. `clip-path: inset(0 0 X% 0)` lifts the bottom edge upward over
   `duration - 1 … duration + overlap` (≈11 frames at 30 fps).
2. Content translates up by up to 34 px so the wipe reads as dimensional.
3. A 5 px caramel rule with a glow sits on the moving edge.

`zIndex: 40 - index` puts **earlier** scenes above later ones. Scene N+1 has already started at
the boundary underneath scene N; scene N clipping itself away is what reveals it. That is why the
transition looks like a reveal rather than a hard cut — and why "fixing" the z-index breaks it.

Because scene N+1's `from` equals scene N's `from + duration`, the wipe overlaps into the next
scene's opening frames. Keep that in mind when placing an entrance animation: the first ~10
frames of a scene are partly covered.

## 4. Layer stack

| Layer | File | Notes |
|---|---|---|
| Paper backdrop | `components/Backdrop.tsx` | rendered once, outside scene sequences, so texture is continuous across cuts |
| Scenes | `scenes/*.tsx` → `SceneShell` | stacked by `zIndex: 40 - index` |
| Audio | `Reel.tsx` → `Soundtrack` | `Sequence` + `Audio`, contributes no pixels |

`Intro.tsx` is transparent and lets the backdrop show through. `Outro.tsx` paints a full-bleed
espresso `AbsoluteFill`, deliberately covering the backdrop for the finale. There is no longer a
persistent chrome layer — labels and notes live inside each scene.

`Backdrop` content: warm radial gradients, a 7-line column grid aligned to the 952 px content
column, a 1 px inner frame at 40 px, and a vignette.

## 5. Voiceover contract

`src/data/voiceover.json` is generated by `scripts/generate-voiceover.mjs` — **never hand-edit**.

```json
{
  "voice": "Brian — Deep, Resonant and Comforting (ElevenLabs)",
  "model": "eleven_v4",
  "lead": 0.12,
  "scenes": {
    "intro": {
      "file": "voiceover/intro.wav",
      "duration": 2.86,
      "startOffset": 0.12,
      "tempo": 1,
      "words": [{ "w": "This", "start": 0.12, "end": 0.36 }]
    }
  }
}
```

- `file` — path relative to `public/`.
- `duration` — length of the processed WAV; `Captions` uses it to fade the block out.
- `startOffset` — 0.12 s caption lead before the first word. **Not** the 4-frame sequence offset.
- `tempo` — `atempo` factor applied to fit the window (1 = untouched, capped at 1.18).
- `words[].start/end` — seconds relative to the WAV, punctuation preserved for display.

`Captions.tsx` exports `VOICEOVER` (the parsed `scenes` map) and highlights the last word whose
`start` is ≤ the current time. Past words dim to 58 % ink, future words to 24 %, the current word
gets a caramel pill. If a scene id is missing from the map, `Captions` returns `null` — a silent
scene with no captions usually means "voiceover not regenerated", not "layout bug".

## 6. Audio graph

```
<Sequence durationInFrames={240}>          music.wav   @ 0.33
<Sequence from={scene.from + 4}>           <id>.wav    @ 1.00   per scene
<Sequence from={SCENE_FROM[scene] + at}>   whoosh.wav  @ 0.16   per cue
```

- **Music** starts at frame 0 and spans the whole composition. It is synthesized locally, so
  there is nothing to license.
- **VO** starts `AUDIO_OFFSET = 4` frames after the cut (`Reel.tsx`). The caption timings
  already include that offset plus the 0.12 s lead — never add a second offset.
- **SFX** are declared as `{ file, scene, at, volume }`; `at` is relative to the scene start and
  may be negative so a whoosh peaks *on* the cut. Shipped example:

  ```ts
  const SFX = [{ file: "whoosh.wav", scene: "outro", at: -6, volume: 0.16 }];
  ```

  Each cue gets a 90-frame `Sequence`, enough for the longest asset and harmless if the reel ends
  first.

SFX files are resolved from `public/audio/` and validated by the checker.

## 7. Scripts

### `scripts/generate-voiceover.mjs`

Runs per scene (or only the ids passed on the CLI):

1. `convertWithTimestamps` → MP3 + character-level alignment.
2. Map characters → narration words. Word `end` is the end of its **last alphanumeric
   character**, because punctuation can carry inflated end times. Non-alphanumeric tokens get a
   40 ms placeholder.
3. Trim quiet head/tail: start 0.04 s before the first spoken character (max 0.3 s), end 0.2 s
   after the last word.
4. Fit the window: usable length is `scene.duration / fps − 0.5 s`; `atempo` up to 1.18×,
   otherwise warn.
5. ffmpeg chain → 48 kHz mono 16-bit WAV:
   `highpass 88`, `-1.2 dB @ 280`, `+1.6 dB @ 3.6k`, `+1.2 dB shelf @ 9k`,
   `acompressor (-18 dB, 2.4:1)`, `loudnorm I=-16 TP=-1.5`, `aresample 48000`.
6. Write `voiceover.json` with timings shifted by trim, tempo and lead.

Partial runs merge into the existing JSON, so re-recording one line does not touch the others.

### `scripts/generate-audio.mjs`

Synthesizes `public/audio/music.wav` and `whoosh.wav` from scratch (no samples):

- **Music** — length derived from `Σ scene.duration / fps` (8 s here), two slow pad chords, a soft
  52 Hz sub pulse every 3 s, filtered air noise, DC blocker, fades, normalized to 0.3 peak.
- **Whoosh** — 0.6 s band-passed noise sweep (160 Hz low cut, moving low-pass, 6.8 kHz
  smoothing). Deliberately soft; it is not a hiss burst.

`node scripts/generate-audio.mjs whoosh` rebuilds a single file.

### `scripts/check-timeline.mjs` (`npm run check`)

The gate. Verifies:

- `fps`/`width`/`height` are sane integers.
- Every scene: unique `id`, positive integer `duration`, `from === previous end`, non-empty
  `narration`.
- Every scene id is registered in `COMPONENTS` in `src/Reel.tsx` (regex over the object literal).
- A `voiceover.json` entry exists, its WAV exists, the read fits the window, caption starts are
  ordered and the last caption ends inside the scene.
- SFX cue scene ids exist and referenced `public/audio/*.wav` files exist.
- Prints the timeline table.

It fails loudly on the mistakes that are painful to find mid-render.

## 8. Helpers

`src/lib/motion.ts`

| Export | Purpose |
|---|---|
| `COLORS` | espresso `#35251D`, cream `#F4E8D5`, caramel `#C58B54`, plus `espressoDeep`, `creamLight`, `caramelDeep`, `latte`, `hairline` |
| `EASE` | `out` `(0.16,1,0.3,1)`, `inOut` `(0.65,0,0.35,1)` |
| `clamp(frame, input, output, easing?)` | clamped interpolation — the workhorse for draws and fades |
| `pop(frame, fps, delay?, config?)` | spring 0 → 1, default damping 18 / stiffness 130 / mass 0.75 |

`src/components/Text.tsx`

| Export | Purpose |
|---|---|
| `Kicker` | `01 — THE START` label with a growing rule; `dark` variant for the outro |
| `MaskedLine` | headline reveal: overflow mask + spring translate from 100 % |
| `withAccent` | splits a title into spans, paints the matching word caramel |

`src/lib/fonts.ts` loads Anton (display), Inter Tight (captions/body), IBM Plex Mono (labels,
notes) through `@remotion/google-fonts`. Scenes reference the exported `ANTON` / `INTER` / `MONO`
constants rather than family name strings.

`src/lib/types.ts` holds `SceneData` (one scene object) and `SceneProps` (`{ scene, index }`).

## 9. Extension points

**Add a scene** — add the object to `scenes.json` (contiguous `from`), create
`src/scenes/MyScene.tsx` taking `SceneProps`, register it in `COMPONENTS`, add SFX cues if needed,
`npm run voiceover -- my-scene`, then `npm run check`.

**Change the look** — `COLORS`/`EASE` in `motion.ts`; fonts in `fonts.ts`; layout constants are
local to each scene (`left: 64`, `right: 64`, captions at `top: 1484`).

**Change pacing** — edit `duration` in `scenes.json`, recompute later `from` values, then
`npm run audio` (music length) and `npm run voiceover` (fitting) as needed.

**Change the wipe** — `SceneShell` owns all of it; scenes know nothing about transitions.

## 10. Gotchas

- Composition id `Reel` is duplicated in `Root.tsx` and `package.json` scripts. Change both.
- `SceneShell` reserves `duration + overlap` frames, so a scene's last 10 frames are shared with
  the next one. Entrance animations that start late will be clipped away.
- The `COMPONENTS` regex in `check-timeline.mjs` expects the literal
  `const COMPONENTS ... { id: Component }` shape. Keep that formatting or update the checker.
- `Audio` comes from `@remotion/media`, not `remotion`. `staticFile()` paths are relative to
  `public/`.
- `voiceover.json` and `public/voiceover/*.wav` are generated artifacts that happen to be
  committed, so the example renders without an API key. Deleting them makes `npm run check`
  fail until you re-run `npm run voiceover`.
- Music is rebuilt with `Math.random()` in the air layer, so its texture changes slightly every
  `npm run audio`. That is expected.
